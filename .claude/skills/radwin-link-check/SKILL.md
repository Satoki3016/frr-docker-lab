# 無線区間の接続・安定性の確認

60 GHz 無線 2 ホップ (`.31 )))無線1((( .32 ─中継─ .33 )))無線2((( .34`) が、計測に使える状態かを確かめる。
作業前に `docs/radwin_lab_rules.md` を読むこと。ラボは lab-bringup で起動済みであること。

完了の条件: 手順 3 の判定が `OK`。

## 手順 1: 設置と設定を確認する (手作業)

**設置** (2026-09-28 時点: 三脚 2 台を約 15 m 離し、三脚Aに .31 と .34、三脚Bに .32 と .33)
- 2 台の三脚のあいだ (電波の通り道) に物を置かない。中ほどでは床・机・棚から約 8 cm 以上離す
  (60 GHz・15 m の第 1 フレネルゾーン半径 約 14 cm の 60%)。
- 通り道が人の通路にかかる場合は、計測中に人が入らないよう周囲に伝える。

**ODU の設定** (Web UI: ブラウザで http://192.168.1.31 〜 .34 を開く。4 台すべて)
| 項目 | 場所 | 値 |
|---|---|---|
| Antenna Selection | Configuration → Wireless | 37dBi (150mm) antenna kit (装着しているレンズと一致させる) |
| Lock to Boresight Beam | Configuration → Wireless | ON (ビームを正面に固定し、自動の切り替えを抑える) |
| TX power backoff | Web UI の該当項目 (ページの場所はマニュアルに記載がない) | 通常の計測では 0 |

設定を保存したら **Web UI を閉じ、2 分待つ**。Web UI を開いたままだと ODU の応答が遅くなり、値が安定しない。
(Tools → Site Survey & Aiming の Aiming は設置時の向き合わせ用。計測中は使わない)

## 手順 2: つながっているか確認する

```bash
sudo python3 scripts/radwin_telemetry.py
```
無線1・無線2 の両方に PHY レートと MCS が表示され、「未接続」がないこと。

リアルタイムで見たいとき (約 2〜3 秒ごとに更新。Ctrl+C で終了。記録は残らない):
```bash
sudo watch -n2 python3 scripts/radwin_backoff_check.py --rounds 1 --no-config
```
通信を流しながらスループットも見たいとき (既定で無線区間に負荷をかける):
```bash
sudo python3 scripts/radwin_live_monitor.py --telemetry 2
```

## 手順 3: 安定しているか判定する (約 3 分)

記録先のフォルダを作る (日付と連番は実際の値に置き換える):
```bash
mkdir -p results/frr/radwin/validation/20260929_running_linkcheck_01
```
負荷をかけた状態で判定する。別のターミナルで `sudo python3 scripts/radwin_live_monitor.py` を動かしたまま:
```bash
sudo bash scripts/sweep_point.sh check_a0_bo0 60
```
- 60 回読み取る (1 回 約 3 秒)。記録先は `validation/` の中で最も新しい `*_running_*` フォルダが自動で選ばれる。
- 最後に表示される `[判定]` を見る。対象は .32 (無線1 の子機) の受信電力。

| 判定の基準 | 見つけるもの |
|---|---|
| 標準偏差 2.0 dB 以下 | 全体の乱れ |
| 前半と後半の中央値の差 3 dB 未満 | 途中で状態が切り替わった記録 |
| 中央値から 6 dB 以上の落ち込み 0 回 | 人の通過 |

`乱れあり` なら、原因 (人の通過・Web UI の操作) を取り除き、**同じラベルで測り直す** (判定は今回の実行分だけで行われる)。
`(参考) ほかの ODU の落ち込み` が出ていれば、経路の近くで何か起きた手がかり。

終わったら、フォルダ名の `running` を `success` (判定 OK) か `fail` に付け替える。

## 参考値 (2026-09-28、15 m・Lock ON・backoff 0・負荷あり)

| ODU | 受信電力 | 送信 MCS |
|---|---|---|
| 無線1 親機 .31 | 約 −49〜−50 dBm | 10〜11 |
| 無線1 子機 .32 | 約 −49〜−51 dBm | 10 |
| 無線2 親機 .33 | 約 −34〜−44 dBm | 7〜9 |
| 無線2 子機 .34 | 約 −42〜−49 dBm | 8〜9 |

## 知っておくべき現象

- **Lock ON でも .32 の受信電力が約 8 dB 上下する 2 つの値 (約 −41 と約 −49 dBm) を行き来することがある。**
  このとき逆向き (.31 の受信電力) は 1〜2 dB しか変わらない。何も操作していなくても起き、きっかけは未解明。
  判定の「前半と後半の差」で見つかるので、その記録は測り直す。
- Web UI と `iw` (スクリプト) は、同じ瞬間なら同じ受信電力を示す。値が食い違うときは、別の時刻に別の状態を見ている。
