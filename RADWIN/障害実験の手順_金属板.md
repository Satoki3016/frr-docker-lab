# 障害実験の手順（金属板）

作成 2026-10-12。対象は実機（LAB_MODE=c2、RADWIN V90 の 2 ホップ）。所要時間は約 75 分。

## 目的

輻輳したまま無線が遮られたとき、AF41 の損失が平常時と比べてどれだけ増えるかを、次の 5 条件で比べる。

| 条件 | 中身 |
|---|---|
| P | 今の方式（優先制御 + 迂回 + 動的制御） |
| P3 | 改良版（経路を先に変える + 容量が小さいときは AF41 だけ CR1 から外す） |
| P4 | P3 + 戻すのを待つ（隣接や MCS が戻っても 10 秒安定するまで CR1 を戻さない） |
| S | 動的制御なし（整形 2160M・重み 6:25:25 に固定。迂回はあり） |
| N | 迂回も動的制御もなし |

2026-10-12 から、有線の経路（CR2・CR3）は隣接 SID で送る（案 A）。どの条件にも同じように効く。

## 準備するもの

- **金属板:** アルミ板、またはアルミ箔を貼った段ボール。大きさはアンテナの前面より一回り大きいもの（30 cm 角以上）。
- **養生テープ:** 板を置く位置の印に使う。
- **時計:** 不要（コマンドが合図を出す）。

## 板を置く位置（毎回同じにする）

- **.31 の正面**に置く。遮るのは無線 1（.31 と .32 の区間）。
  - 2026-10-12 の人が立つ実験で実際に遮れたのは .31 だった。
- アンテナの前面から **約 15 cm**、前面と平行に、前面全体を覆う位置に置く。床または台に養生テープで印を付ける。
- 三脚とアンテナには触れない（向きがずれると、そのあとの全部の回が比べられなくなる）。
- 板を置いたら、その場を離れる。人の体で電波を遮らないようにする。

## 1. 実機に戻す（1 行ずつ）

```
sudo bash scripts/frr_down.sh
```
```
sudo bash scripts/check_nic_hijack.sh
```
```
sudo env LAB_MODE=c2 bash scripts/frr_all_up.sh
```
```
sudo pkill -f frr_te_monitor.sh
```

## 2. 観測を始める

```
sudo python3 scripts/radwin_observe.py start --no-start-probe
```

始めるときに経路と QoS の設定（frr_dscp_te.sh）が掛け直され、有線の経路に隣接 SID が付く。

## 3. 確認（数秒）

```
sudo docker exec LER_Ingress ip route show table 41
```

- `leri-cr2` と `leri-cr3` の行が `encap mpls 15xxx`（15000 台）になっていること。
- `leri-cr1` の行が `encap mpls 16005` になっていること。
- 16005 が 3 本とも並んでいたら案 A が効いていないので、ここで止めて知らせる。

## 4. 基準（障害なし、約 23 分）

窓と三脚に近づかない。

```
sudo python3 scripts/radwin_observe.py fault --label none --condition P,P3,P4,S,N --count 2 --shuffle
```

## 5. 金属板（30 秒、約 35 分）

```
sudo python3 scripts/radwin_observe.py fault --label plate30 --condition P,P3,P4,S,N --count 3 --shuffle --duration 30
```

- 最初に順番が表示される（1 巡ごとに入れ替わる）。順番は `06_system/fault_plan.csv` に残る。
- 各回に、次の合図が出る。
  - 「あと 10 秒で置く。準備」
  - 「今、置く」→ 印の位置に板を置き、離れる
  - 「今、外す」（置いてから 30 秒後）→ 板を外し、離れる
- 合図から 1〜2 秒ずれても構わない。遮られた区間は、受信電力と ping の記録から割り出す。
- 計測が終わると AF41 の損失率が表示され、すぐ次の回が始まる。

## 6. 基準をもう一度（約 12 分）

```
sudo python3 scripts/radwin_observe.py fault --label none --condition P,P3,P4,S,N --shuffle
```

始めと終わりの基準を比べて、実験中に無線の状態が変わっていないことを確かめる。

## 7. 止める

```
sudo python3 scripts/radwin_observe.py stop
```

## 見るもの（集計で自動的に出る）

`results/frr/tools/summarize_rain_observation.py` の報告書の「条件ごとの比較」の表を見る。

| 列 | 意味 |
|---|---|
| 遮られた区間の損失 [個/秒] | 主な指標。遮られた区間（前 3 秒・後ろ 5 秒を含む）に失った AF41 を秒数で割った値 |
| AF41 損失率 | 120 秒全体の値。遮られた長さで薄まるので補助 |
| 受信側の取りこぼし | 0 であること（0 でなければ計測の誤差が混ざっている） |
| CR2/CR3 出口の AF41 破棄 | 0 であること（送り返された分が溢れても AF41 が守られている） |

あわせて、各回の `route_events.log` で、CR2 の 16005 が消された時刻に AF41 が落ちていないこと（案 A の実機での確認）を見る。

## うまくいかないとき

- **「電波の落ち込みを検出できなかった」と出る回が続く:** 板の位置がずれている可能性。印の位置と向きを確かめる。
- **板を外しても無線が戻らない（MCS が低いまま、または未接続）:** 次の回を止め（Ctrl+C）、`sudo python3 scripts/radwin_observe.py status` で状態を見る。数分たっても戻らなければ知らせる。
- **途中でやめる:** Ctrl+C で fault を止めてから、7 の stop を行う。それまでの回は残る。
