# 失敗記録: MTU 超過でトラフィックが流れず

日付: 2026-09-11
タグ: 20260911_radwin_cr1_wireless (改名前)

## 症状
`normal` と `failure` のスループットがほぼゼロ (316〜1010 bytes/s)。
`failure_reroute` のみ、有線 CR2 へ迂回している t=25〜46 の間だけ 8.04 Gbps が出た。

## 原因
`frr_measure.sh` の iperf3 が **`-l 8950`**（8950バイトのデータグラム）固定だった。

```
8950(データ) + 8(UDP) + 20(IP) + 4(MPLSラベル) = 8982 バイト
```

CR1 は 60GHz 無線経由で `cr1-lere` の **MTU が 7800**。8982 > 7800 のため送信できず破棄。
CR2/CR3 は MTU 9100 なので通る → 迂回中だけ流れた。

**MPLS の透過性の問題ではない**（OSPF 隣接も ping も無線越しに成立していた）。

## 対処
`IPERF_DGRAM` を `lab_config` に追加し、`LAB_MODE=c2` では **7000** を使うようにした
(`7000+32 = 7032 < 7800`)。他モードは従来どおり 8950。
`run_all_scenarios.sh` の起動時表示にも出るようにして、次回から目視確認できるようにした。

修正後の結果: `20260911_success_radwin_cr1_wireless/`
