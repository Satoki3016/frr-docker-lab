# 雨の観測 (100 m・窓ガラス 2 枚越しの 60 GHz 無線区間)

雨 (主に窓の水の膜) で無線の容量が落ちたとき、動的制御と迂回が追従し、AF41 が守られるかを数日観測する。
仕組みは `scripts/radwin_observe.py` (start / status / stop)。

## フォルダ名の読み方

`始めた日[-終わった日]_結果_目的_連番`

- 日付をまたいだ観測は、始めた日のあとに終わった日 (月日) が付く。例: `20261002-1003_` は 10/02 に始めて 10/03 に止めた。
- 結果は `running` (観測中)・`success` (正常に止めた)・`fail`。
- 集計スクリプトなどには、終わった日と結果を省いた名前 (例 `20261002_rainobs_04`) でも渡せる。

## 各フォルダ

| フォルダ | 期間 | 位置づけ |
|---|---|---|
| `20261003_running_rainobs_02` | 10/03 18:41〜 | **本番の観測 (実行中)** |
| `20261002-1003_success_rainobs_04` | 10/02 21:24〜10/03 18:14 (約 21 時間) | **晴れの日の基準データ** (雨なし、全負荷計測 91 回すべて成功)。10/03 02:13 以降は「容量低下」の判定が誤り (計測の理由の欄だけ。データは正常) |
| `20261003_success_rainobs_01` | 10/03 18:19〜18:41 | 判定基準の修正を反映するための起動し直しのあいだ (短い記録) |
| `20261002_success_rainobs_01`〜`_03` | 10/02 20:16〜21:24 | 気象・ナウキャスト・ping などを足すたびに起動し直した短い記録 |
| `20261002_success_trial_01` | 10/02 20:05〜20:13 | 実機での 10 分の試運転 (合格) |
| `20261002_success_vethtest_01` | 10/02 17:50〜20:00 | 仮想環境での確認 (偽の ODU、V1〜V5 すべて合格。判定は `01_report/judgement.txt`) |

## 1 つの観測フォルダの中 (詳しくは各フォルダの README.md)

| フォルダ | 中身 |
|---|---|
| `01_report/` | 途中経過の報告書 (6 時間ごと)、集計表、時系列の図。**まずここを見る** |
| `02_fullload/` | 全負荷計測の一覧 (`probes.csv`) と 1 回ごとのフォルダ |
| `03_radio/` | 4 台の ODU と ping。ファイルは日付ごと (`odu_YYYYMMDD.csv`) |
| `04_control/` | 動的制御・経路表・HTB・OSPF/BFD・te_monitor |
| `05_weather/` | アメダス名古屋と実験場所のナウキャスト |
| `06_system/` | 観測の運転の記録 (欠測の検査 `check.txt` など) |

実行中の観測 (`running`) は、止めたときにこの並べ方へ自動で整理され、日付をまたいでいれば終わった日が名前に付く。
